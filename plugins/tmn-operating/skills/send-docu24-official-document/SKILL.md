# Send Docu24 Official Document

문서24에는 발송 API가 없으므로, 사용자의 로컬 브라우저에 로그인된 세션으로 작업한다. 공문 내용은 LLM이 만들 수 있지만, 수신기관·본문·첨부파일·최종 발송은 각각 검증 가능한 입력과 화면 상태로 다룬다.

## 시작 전 확인

- 문서24에 로그인된 사용자 브라우저를 사용한다. 로그인, 인증서 입력, CAPTCHA, 보안 경고 우회는 사용자에게 맡긴다.
- 작업할 공문 데이터를 구조화해 확인한다. 재작성은 `mode: rewrite`와 기준 공문을 식별할 `source_document`가 필요하다.
- 첨부파일은 실제 로컬 경로를 확인하고, 문서24의 첨부 제한(총 500MB)과 조직의 개인정보·보안 규칙을 확인한다.
- 이전 공문·테스트 공문에 포함된 수신자 연락처나 본문, 첨부파일을 새 공문의 기본값으로 가정하지 않는다.

권장 입력 형태:

```json
{
  "mode": "new | rewrite",
  "source_document": "재작성할 보낸 공문을 찾는 제목·날짜·수신기관",
  "recipient": "받는 기관의 정확한 명칭 또는 검색어",
  "title": "문서 제목",
  "body": "본문",
  "attachments": ["/absolute/path/to/file.pdf"]
}
```

`source_document`는 `rewrite`일 때만 필요하다. 발신자명, 제출자, 직인날인, 알림수신번호, 문서번호 직접입력은 사용자가 별도로 제공하거나 기존 조직 설정을 유지한다.

## 새 공문 작성

1. 문서24 홈에서 **문서 보내기**를 연다.
2. 문서 제출 전 확인 사항 4개를 각각 확인하고 `예`로 선택한다. 해당 조건이 사실이 아닌 경우 진행하지 않는다.
3. **받는기관 검색**으로 기관을 찾아 선택한 뒤, 화면에 반영된 기관명이 요청의 수신기관과 정확히 일치하는지 확인한다.
4. 제목, 본문, 필요 시 직인·발신자·제출자·문서번호를 설정하고 첨부파일을 추가한다.
   - 본문은 웹한글기안기 편집 영역에 입력하고, 기존 본문이 있으면 의도적으로 전체 교체인지 추가인지 확인한다.
   - 문서24는 외부 자료를 붙여넣으면 수신처에서 비정상적으로 보일 수 있다고 안내한다. 실제로 보이는 문서 형태는 미리보기 PDF에서 확인한다.
5. **전송요청**으로 미리보기 팝업을 연다.

## 보낸 공문 재작성

1. **문서함 → 보낸 문서함**에서 기준 공문을 찾고 상세를 연다.
2. 상세 화면 하단의 **재작성**을 사용한다. 수정·다운로드·PDF 보기 기능으로 대체하지 않는다.
3. 재작성된 문서를 새 공문으로 취급한다. 특히 다음을 새 요청값으로 명시적으로 교체하거나 유지 여부를 확인한다.
   - 받는기관: 다시 검색하고 선택한다.
   - 제목과 본문: 요청된 새 내용으로 교체한다.
   - 첨부파일: 기존 파일을 유지·삭제·교체할지 확인한다.
   - 직인, 발신자, 제출자, 문서번호, 알림수신번호: 조직 기본값을 그대로 둘 수 있는지 확인한다.
4. **전송요청**으로 미리보기를 연다.

## 미리보기와 발송

전송요청 팝업에는 PDF 미리보기, 첨부파일 목록, **수정**, **보내기**가 있다. `보내기`는 실제 대외 공문을 발송한다.

발송 직전에 다음을 화면에서 다시 대조한다.

- 수신기관과 제목
- 본문의 핵심 요청·날짜·금액·인명 등 영향이 큰 내용
- 첨부파일 이름·개수·용량
- 직인, 발신자, 제출자, 문서번호

시연·초안 작성·미리보기 요청만으로는 `보내기`를 누르지 않는다. 실제 발송은 사용자에게 발송 직전 확인을 받고 수행한다. 발송 후에는 보낸 문서함에서 발송 상태와 문서번호를 확인해 결과를 알린다.

## 중단과 복구

- 수신기관이 여러 개이거나 검색 결과가 불명확하면 추측하여 선택하지 않는다.
- 화면 문구나 단계가 달라져 검증할 수 없으면 현재 화면을 기록하고 사용자에게 확인을 요청한다.
- 인증·보안·CAPTCHA 단계는 사용자가 처리한 뒤 계속한다.
- 재시도 전에 보낸 문서함을 확인해 중복 발송이 아닌지 먼저 검증한다.
